## 2. Explicit Catalog/Article strategy (implemented)

- [x] 2.1 Reserve `_strategy: 'catalog' | 'article'` as reserved template metadata (`getExtractionStrategy` in `_catalog_sections.ts`), following the existing `_description` convention (never wrapped as an extractable field — excluded in `_evidence_template.ts`'s `wrapSchema`, `splitNode`, and `splitEvidenceResult`'s own top-level loop) and excluded from `findPrimaryArrayKey`'s "sole top-level key" count
- [x] 2.2 **Design correction found during implementation**: `_strategy` does NOT travel through `SchemaNode[]` ↔ template conversions — `schemaNode.ts` has no root-metadata slot to hold a whole-schema-level flag (only per-group `description`, attached to individual field nodes). Instead, `_strategy` is separate React state in `App.tsx` (`extractionStrategy`), reset only when a new PDF is opened (see group 3 — it must survive schema generation, not reset after it), and merged in only at the request boundary `useExtraction.ts` already uses for its `{ records: [template] }` wrapper — now `{ records: [template], _strategy: extractionStrategy }`, a sibling key, not nested inside the researcher's own schema fields
- [x] 2.3 Gate `extractWithModel`'s sectioning attempt on `getExtractionStrategy(template) === 'catalog'`; any other value or missing key always takes the single whole-document path, regardless of `findPrimaryArrayKey`/`splitMarkdownByHeadings` results
- [x] 2.4 Add a Catalog/Article `SegmentedControl` to `SchemaPanel`'s header (next to the existing Fields/JSON view toggle), wired through `RightRail` to `App.tsx`'s `extractionStrategy` state
- [x] 2.5 Tests: strategy gating in `_model.test.ts` (catalog-strategy schema sections, article-strategy schema with a heading pattern that would otherwise qualify never sections, unset-strategy schema never sections), `_strategy` drop/passthrough in `_evidence_template.test.ts` (`wrapTemplateWithEvidence` and `splitEvidenceResult`). No `schemaNode.ts` round-trip test needed per 2.2's correction — `_strategy` never enters that pipeline. No hook-level test added for `useExtraction.ts`'s request-wrapping change (this codebase has no hook-testing infra/`@testing-library` dependency yet; covered by TypeScript's signature check plus the backend gating tests, which are what actually matters for correctness)
- [x] 2.6 Behavior-change note: gating sectioning behind `_strategy` narrows today's live auto-sectioning behavior for schemas without `_strategy` set (new default is `'article'`-equivalent, i.e. never auto-section) — recorded in design.md's Migration Plan; call this out explicitly if/when this change is committed

## 3. Strategy chosen before schema generation, shaping the generation prompt (implemented)

- [x] 3.1 Move the Catalog/Article `SegmentedControl` in `SchemaPanel`'s header out of the `ready`-only gate so it is visible and usable in every schema state (idle, generating, error, ready) — the researcher's choice needs to be available before clicking "Generate schema", not only after
- [x] 3.2 `App.tsx`'s `extractionStrategy` state must survive schema generation (stop resetting it to `'article'` on generation success — it was chosen *for* this generation) while still resetting on a new PDF open (a genuinely new document/schema context)
- [x] 3.3 `_schema.ts`'s `schemaPrompt` takes an optional `strategy` parameter: for `'catalog'`, replace the existing "design a repeating field as an array" guidance with the opposite instruction — describe the shape of ONE occurrence directly, since per-section extraction (capability 1) already supplies the repetition; the pre-existing array-oriented guidance is kept, unchanged, for `'article'`/unset
- [x] 3.4 Thread `strategy` through `generateSchemaWithModel` (`_model.ts`), `generate_schema.ts`'s form parsing, `api.ts`'s `requestSchema`, and `App.tsx`'s call site
- [x] 3.5 Tests: `_schema.test.ts` covering catalog vs. article vs. unset guidance text, including that the two guidance styles are mutually exclusive (catalog wording never coexists with the old array-oriented wording)
- [x] 3.6 Switching the strategy (Catalog ↔ Article) once a schema already exists (`ready` or `error` state) automatically regenerates it — a schema generated under the old strategy's guidance no longer matches the new one, so leaving it in place would silently mismatch. `generateSchema` takes an explicit `strategy` parameter (defaulting to current state) rather than relying on `extractionStrategy` from the closure, since a state update triggered in the same handler isn't visible until the next render. No regeneration from `idle` (nothing generated yet).
- [x] 3.7 UI polish found alongside this work: `SchemaPanel`'s header showed a hardcoded filename regardless of the actual open document — now reads `documentFileName`, threaded from `App.tsx`'s `pdfSource` through `RightRail` (which already held it for `ChatTab`). Also split the header into two rows (title; then the two `SegmentedControl`s) since both controls plus a longer real filename crowded one row at the rail's minimum width.
