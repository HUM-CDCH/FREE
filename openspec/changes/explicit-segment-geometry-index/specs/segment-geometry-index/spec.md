## ADDED Requirements

### Requirement: Evidence scopes have deterministic segment identities
Studio API SHALL attach `segment_id` to every valid Evidence `source_scope`.
For Catalog extraction, the ID SHALL identify the original heading-derived
section input. For Article extraction, the ID SHALL identify the one
full-document input. The ID SHALL be generated by Studio API and SHALL NOT be
generated by the model.

#### Scenario: Catalog calls complete out of order
- **WHEN** Catalog section calls complete in a different order from their
  source sections
- **THEN** each retained Evidence leaf retains its own section's `segment_id`
- **AND** no Evidence leaf inherits another completed call's identity

#### Scenario: Empty section result is filtered
- **WHEN** a Catalog section produces an empty result and is excluded from the
  merged records array
- **THEN** retained later records keep their original source segment IDs
- **AND** their IDs are not renumbered from merged record positions

### Requirement: Tables receive at most one segment assignment
The frontend SHALL build a geometry index from unique Evidence source scopes.
It SHALL assign a parsed table to one segment only when that table's canonical
Markdown view is uniquely placeable within exactly one scope. A table with no
unique owner SHALL remain unassigned.

#### Scenario: Two records share one PDF page
- **WHEN** two Catalog segments have distinct uniquely placed tables on one
  PDF page
- **THEN** each table is assigned to its own segment ID
- **AND** no table appears in both geometry entries

#### Scenario: Repeated table view is ambiguous
- **WHEN** a table Markdown view is repeated such that it cannot identify one
  source scope
- **THEN** the table is absent from every geometry entry
- **AND** no page or occurrence fallback assigns it
