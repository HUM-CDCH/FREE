# Grounding Lab — review handoff

Updated 2026-09-01 — status: pipeline evaluation concluded; the LLM comparison
and production decision remain provisional. Pipeline numbers reflect the
post-review harness (fixture excluded, row-context containment fixed). Every
LLM section in REPORT.md predates strict response validation and is historical.

## What this is

A standalone experiment (nothing in FREE is touched) answering: **can a
tiered non-LLM pipeline replace LLM-based evidence grounding, with an honest
per-link confidence score?** Evidence grounding links each extracted scalar
(claim = resultPath + value) to the document passage (evidence anchor) that
supports it; today the extraction LLM does this with no confidence signal
(`groundingModelFor`, `prototypes/studio/api/_extraction_runtime.ts`).

## Current conclusion (LLM comparison provisional)

The pipeline evidence is current on 10 documents / 177 claims with a proper
dev/held-out split. At the incumbent constants it gets 73/85 held-out links,
19/25 abstains, and 66/66 auto-accepted links correct (95% CI 94–100%).

No current pipeline-versus-LLM ranking is available. Every LLM row was scored
before strict batch validation and still counts the `_smoke` fixture. Those
historical runs remain useful diagnostics, including the observed context-
window truncation failure, but must not support an accuracy or latency decision
until the compared models are rerun on the 177-claim dataset.

## Layout

- `grounding_lab/pipeline.py` — normalization, lexical tier (word-boundary
  containment), bi-encoder shortlist, cross-encoder / NLI scorers, margin
  confidence, verbatim-containment post-check. Model ids are constants at top.
- `grounding_lab/harness.py` — runs 7 configs, prints REPORT.md content.
- `grounding_lab/calibrate.py` — dev/held-out split, sweeps the policy
  constants on dev only, prints CALIBRATION.md content (incl. recall@K).
- `grounding_lab/llm_baseline.py` — incumbent-shaped LLM baseline (per-record
  batching, bracketed anchors, `{"links":{...}}`), local Ollama.
- `scripts/dump-anchors.mts` — anchors.json from a parsed document via the
  FREE `canonicalAnchorInventory` (adds table-row context).
- `dataset/<doc>/{parsed_document,anchors,claims}.json` — 10 documents,
  177 hand-labeled claims (129 linkable, 48 must-abstain incl. ~30
  adversarial near-variants); the `_smoke` fixture is excluded from
  evaluation. Dev = the 5 original docs (constants were tuned watching
  them); held-out = the 5 added afterwards (herredsvejen, hvissinge,
  katrinesminde, age-related-disease, catfish-collagen).
- `tests/test_pipeline.py` — 29 checks (lexical tier, routing, downgrade,
  guards, response parsing, fixture scope, and label validation).
- `REPORT.md` — full-dataset results + LLM baseline (auto-generated; do not
  hand-edit: harness output + llm_baseline output appended).
- `CALIBRATION.md` — dev-sweep + held-out results (auto-generated by
  `pnpm --filter grounding-lab calibrate`; do not hand-edit).

## How to run

```bash
pnpm --filter grounding-lab install:python   # uv sync; CUDA torch on cu130
pnpm --filter grounding-lab test
pnpm --filter grounding-lab harness          # regenerates REPORT.md content
pnpm --filter grounding-lab calibrate        # regenerates CALIBRATION.md content
uv run --no-sync python -m grounding_lab.llm_baseline dataset   # needs Ollama
```

CPU works; an NVIDIA GPU makes the neural tiers ~50 ms/claim. Run harness and
Ollama sequentially — sharing the GPU skews latency badly.

## Key numbers (held-out documents, never seen during tuning)

- lexical+ce-bare at incumbent constants (K=10, abstain 0.5, cap 0.25,
  accept 0.5): 73/85 links, 19/25 abstains, 7 wrong, auto-accept 66/66.
- Dev-swept constants (abstain 0.7, cap 0.1, accept 0.3) perform the same
  on held-out (72/85, 19/25, 6 wrong, 66/66 auto) — the incumbent constants
  are not overfit in any way that matters; keep them.
- Auto-accept precision is 100% in every config on the full 177-claim set,
  and held-out results are unchanged after the row-context containment fix
  (the hole was real but no wrong sibling-cell link was being rescued in
  this dataset).
- Historical LLM baselines (pre-strict-parser and pre-fixture-exclusion;
  do not use these rows for the production decision):

  | model | held-out | wrong (full set) | ms/claim | where |
  |---|---|---|---|---|
  | gpt-5.6-luna@high (codex CLI) | 110/110 | 5 | 1651 | OpenAI API |
  | gpt-5.6-luna@medium | 109/110 | 6 | 1265 | OpenAI API |
  | qwen3.8:27b, thinking | 109/110 | 4 | 8594 | DGX Spark |
  | gpt-5.6-luna@low | 108/110 | 10 | 1196 | OpenAI API |
  | qwen3.8 (local) | 106/110 | 9 | 1466 | RTX 4090 |
  | pipeline lexical+ce-bare | 92/110 | 12 | 42 | RTX 4090 |
  | qwen3:32b, no thinking | 63/110 | 79 | 7252 | RTX 4090 |
  | G9v3-3B (bartowski Q8) | 47/110 | 94 | 626 | RTX 4090 |

  In those historical runs, gpt-5.6-luna@high abstained perfectly (49/49,
  including every adversarial near-variant). qwen3:32b without thinking linked
  nearly every trap; a probe
  shows thinking restores abstention at ~46 s/claim. nemotron-3-super:120b
  was aborted (impractical latency on the Spark). G9v3-39A5B is unrunnable
  on current infrastructure: every available llama.cpp build (Spark Ollama,
  local Ollama, Docker Model Runner) rejects the 'g9v3' architecture, and
  the safetensors path needs a 78 GB download with no serving stack.
- Shortlist recall@K on the neural-fallback population (item 3, answered):
  held-out recall rises 17/25 (K=10) → 22/25 (K=20) → 24/25 (K=30).
  The dev sweep is insensitive to K (dev misses are unreachable-by-any-K),
  so raising K to 20–30 is cheap insurance for recall on unseen documents —
  worth adopting despite the dev-only sweep not selecting it.

## Dataset-labeling method (new docs)

Claims were authored from the anchor dumps. `label_review` now enumerates the
complete bounded-containment hit set across all 10 evaluated documents using
the pipeline's shared matcher. Missing gold ids and containment hits for
must-abstain claims fail validation. Exact hit/gold sets are machine-verified;
the 18 current mismatches are printed with their notes for human review because
they are deliberate paraphrases or contextual evidence ambiguities.

## Review history

Two independent adversarial reviews shaped the pipeline (findings and fixes
unchanged from the previous handoff):

- Review 1 (Opus): `nli-only` routing bug, lexical substring hole, score/
  margin conflation, calibration-bucket blindness, context leakage, missing
  LLM baseline. All fixed.
- Review 2 (gpt-5.6-sol): baseline not production-shaped, neural auto-accept
  overstated, disputed gold label, protocol failures scored as abstentions,
  interface gap (field names unavailable in production). All fixed — the
  containment post-check and `-bare` variants came from this.
- Review 3 (Fable + gpt-5.6-sol, merged): row context bypassed the
  containment post-check (a wrong sibling table cell kept full confidence
  whenever the value appeared anywhere in its row — fixed to check the
  cell's own text, in `verbatim_downgrade` and `calibrate.py` both); the
  `_smoke` fixture was counted as a document (now excluded from
  `load_dataset`); the baseline parser accepted flat claim maps production
  rejects (now mirrors `groundingSelections`' batch validation and exact
  selection labels); `label_review` printed but never failed (now validates
  every evaluated document and reports complete hit/gold mismatches);
  REPORT's headline shortlist recall was measured with rendered claims
  while the recommended config queries bare values (now reports both).

Post-review work (previous iteration): dataset 72 → 182 claims across 11
dirs, dev/held-out split with dev-only recalibration (`calibrate.py`),
recall@K measurement, LLM baseline rerun on the full set.

## Known limitations / still open

- Held-out n=110 claims across 5 documents — enough to see generalization,
  small enough that ±1 claim moves a percent.
- 1 held-out gold is outside even the top-50 shortlist (unreachable); 2 dev
  golds likewise. Raising K cannot recover those.
- Confidence needs a contract + persistence decision (`GroundingSelection` /
  `EvidenceLink` have no such field today).
- Production `anchorText()` degrades table-cell text (keeps only the first
  cell per row); the lab deliberately bypasses it — productionizing means
  fixing that in `grounding.ts`, not adopting it.
- HF model ids are unpinned (no revision hashes).
- In the historical LLM baseline, qwen3:32b (Q4, thinking disabled) linked
  correct anchors for real claims but fell for nearly every adversarial
  near-variant ("543 g" → the
  542 g anchor), scoring 3/49 on abstains — worse than the 8B model.
  A probe shows thinking mode restores abstention (5/7 vs 1/7 on
  brondbylund's traps) at ~46 s/claim; a full `--think` run is in flight
  (`llm_baseline.py --think`). The context-truncation incident is direct
  evidence that the incumbent per-record-call architecture silently degrades
  on large documents unless the window is sized to the anchor inventory.
- New-doc gold labels were authored and verified by the agent in one pass;
  the REVIEW-marked multi-gold calls deserve the same human skim the
  original documents got.
- The dataset skews verbatim: claims were authored from the anchor dumps
  and reviewed with the pipeline's bounded containment, so values
  are biased toward strings that appear verbatim in the document. Real
  extractor output paraphrases (ISO dates, normalized units, translated
  fields); only a handful of deliberate paraphrase cases exist (`Im Dol
  2-6`, `1300 m2`, `2004-08-13`, `Carlos José Dias Pereira`). The lexical
  tier's zero-wrong-link record is partly a property of the dataset, not
  only of the tier.
- The LLM baseline sections in REPORT.md were scored with the earlier
  permissive parser (a flat top-level claim map counted as links);
  production rejects that shape. Rerun `llm_baseline` to refresh them —
  models that answered with the exact `{"links": {...}}` shape are
  unaffected.

## Decision to make (human)

The pipeline-only questions are answered: held-out generalization holds,
recalibration confirms the incumbent constants, and shortlist recall supports
raising K to 20–30. The pipeline-versus-LLM choice is not answered until at
least the decisive local baseline is rerun under strict validation. After that,
choose between more evaluation and production integration; do not infer a
hybrid or full-LLM advantage from the historical leaderboard.
