# Explicit model provider adapters and discovery

FREE supports seven explicit Model Connection kinds: Ollama, OpenAI, Anthropic, Google, Codex CLI, Claude Code, and generic OpenAI-compatible. Each connection stores the base URL expected by its adapter. Ollama stores its server base and reaches `/api/tags`, `/api/chat`, and `/api/generate` beneath it; the generic adapter guarantees `/models` and `/chat/completions` beneath its exact stored base. Native-provider custom bases retain their selected native contracts. Provider names, defaults, credential modes, discovery, construction, and concrete capabilities live once in the backend provider registry. Only serializable UI metadata crosses the configuration API.

Discovery is advisory, bounded, and ephemeral. It reports current connectivity and offers a session-only model catalog without generating model content, persisting status, changing credentials, or gating Apply. Researchers may enter any non-empty model ID; execution later passes that exact ID to the selected provider even when discovery omitted it. Claude Code has no dynamic model-list operation, so a successful installation/authentication check suggests the documented `fable`, `opus`, `sonnet`, and `haiku` aliases without restricting manual IDs.

All general model execution uses AI SDK v7. Resolving a general Capability Route returns the SDK's `LanguageModel` directly rather than a FREE-owned generation wrapper. Each provider adapter declares whether schema-less JSON output is native or prompt-based and whether explicit temperature is supported. An explicitly supplied temperature fails before invocation for Codex CLI and Claude Code. NuExtract's raw Ollama protocol remains the explicit specialized Extraction execution profile.
