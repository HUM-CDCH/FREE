## Authority and integration seam

Adopt [ADR 0017](../adr/0017-durable-extraction-control-and-call-checkpoints.md): DBOS continues durable workflow execution and dispatch, while durable researcher control, call captures, unit checkpoints, and feedback publication live in a restricted `extraction_runtime` namespace in the existing PostgreSQL database. No Redis, new database, service, or competing scheduler.

Studio owns authenticated admission, schema/selection edits, review, and feedback publication. Its app role reads the coordination namespace for status/results/selections and writes control, selections, sanitized feedback, and dispatch handoffs. The Parsing worker owns execution and checkpoint validation via narrow coordination routines. Its read-only API still serves canonical artifacts and has no database connection. The worker gets no app `public` access, no Studio `dbos` access, and no direct coordination-table access. Studio writes app review records and their sanitized feedback revisions in one PostgreSQL transaction. Worker routines operate only on sanitized admitted inputs and the coordination namespace; never researcher account configuration or credentials.

Researcher-visible status is derived from durable control intent plus current execution/coverage/acknowledgement in this namespace. DBOS attempt status is diagnostic: a paused attempt may return successfully. There is no second mirrored status in `public`. Preserve historical Extraction columns and old outcomes; a version-aware reader chooses legacy interpretation versus linked new-protocol execution state. Root README and ADR 0012 require an explicit Extraction-specific amendment when implementing, rather than pretending the old DBOS-only status contract still applies.

## Persistence records

These are logical record boundaries; authored SQL names may follow repository conventions, but ownership, keys, immutability, constraints, and transactions are required.

| Record | Required content / invariants |
| --- | --- |
| Runtime head | One per Extraction: protocol capability, immutable source/strategy pins, opaque project scope, selected execution-input ID, control intent/revision, current attempt fence and lease epoch, current plan/snapshot references. Versioned compare-and-set; no credentials. |
| Execution selection | Immutable ordered selection: producing Schema Revision/tree hash, validated requested/effective method/models, resolved defaults/prompt/tokenizer versions and budgets, source generation. Saved pending selection separate from adopted head; selection IDs never rewritten. |
| Execution attempt | Unique internal ID, Extraction ID, immutable selection ID and originating fence, DBOS workflow ID, bounded lease/heartbeat state, acknowledgement/outcome/error. Control/lease authorization is mutable separately from immutable attribution. |
| Work plan manifest | Immutable generation/revision, planner version and input digest, stable source/record scopes, primary coverage versus context overlap, stage dependencies, planned unit ordinals, carry-forward references, explicit reprocessing selection. Publish each dependent unit set atomically before admitting it. |
| Unit capture | Unique `(Extraction ID, plan generation, stage, stable scope, manifest ordinal)`: producing selection, original attempt, latest committed feedback/candidate revision, captured source context references, provider role, status. Insert once before provider work; replay finds this key without consulting today's feedback. |
| Unit input | Append-once finalized prompt/request and selected correction revisions, input digest, composer/tokenizer/model identity and counted budgets. Durable before invocation. Never recompose a started input on recovery. |
| Unit checkpoint | Append-once result/output plus processing stage, input digest, producing schema/settings, canonical source Evidence/proposal state, large artifact reference/hash if needed. Duplicate same capture/input yields existing result; mismatched duplicate rejected. |
| Result snapshot / values | Stable result/record/field IDs, immutable model versions and producing attribution, evidence/processing state and coverage. Ordered snapshot sequence references immutable values; array order/path is presentation only. |
| Correction/review revisions | App-owned versioned per-result/field decisions, original producing schema, typed reviewed value, optional own-source anchors, active/superseded/excluded state, optimistic review version. Separate from model values; no model write owns these rows. |
| Feedback head/revision | Project-scoped monotonic head, append-only sanitized correction candidates with schema/meaning/type context, source/example context, inclusion and grounding state. Updated atomically with correction save/supersession/exclusion. Compatibility is per consuming selection. |
| Artifact references | Durable reference graph from source revisions, captures/checkpoints/results, Evidence, review history, and feedback contexts. Hash/generation/namespace validated. Reachability, not activity/terminal state, governs retention. |
| Dispatch handoff | Transactional record for a committed attempt versus DBOS enqueue receipt. Deterministic enqueue identity, retriable reconciliation; no alternative execution scheduler. |

Existing SchemaNode IDs are retained across renames; added nodes get fresh identity. Historical results/reviews need deterministic legacy identities bound to their original artifact/path, not a guessed mapping to a reordered new result. Article document scope, Catalog discovered source anchors, and explicit lineage for split/merged/reprocessed records must be distinguished. Ambiguous mapping creates a retained historical value needing review, never implicit correction transfer.

## Transactions, capture, and fencing

1. **Command:** Studio checks authenticated ownership and expected control revision, commits command ID/intent plus revision, and records a dispatch handoff where needed. Same command ID/payload replays; mismatched reuse or stale conflicting command returns conflict. Resume received during Pausing is a durable pending request: intent remains PAUSE, no new captures start, and only acknowledged drain schedules the linked attempt. Later parameter editing/saving cancels an earlier pending Resume, keeps the boundary Paused, and shows “Changes pending — apply or discard, then resume”; it must not auto-run an old selection while new edits await adoption. A later Stop also cancels pending Resume. STOP is terminal intent for every protocol; subsequent Resume/Retry is refused. Control visibility does not depend on ephemeral browser polling.
2. **Feedback save:** Studio locks the project's feedback head, validates correction under its producing schema/source, appends review/candidate revision, updates head, and commits atomically. Allocate revision under the lock; do not infer ordering from timestamps, sequence reservation order, or `max(revision)` over racing transactions.
3. **Capture:** Use explicit READ COMMITTED transactions. Lock the feedback head FOR SHARE first, then Extraction control/lease head in a consistent order; read the head after acquiring its lock. Correction writes take FOR UPDATE on the same feedback head. Under these short locks, verify current lease/fence/selection, check an existing capture/checkpoint, reject new work unless intent RUN, and bind a new capture to the latest committed feedback head. That transaction is the defined start/admission boundary. Corrections committed after it affect later captures, even if the provider network send occurs later. If the repository's transaction adapter uses SERIALIZABLE instead, serialization failures must be retried and the same locked-head guarantee demonstrated; do not accidentally rely on a stale snapshot.
4. **Compose:** From the pinned candidate revision, apply versioned schema-compatibility/relevance rules and counted prompt budgets; persist the exact finalized input row before invocation. Required source/instructions/reply reserve take precedence; omit oversized examples and record why. Do not truncate required source or corrected values to fit. A captured but uninvoked unit can be halted before sending if control changed; it remains unfinished with its captured context.
5. **Call/commit:** No SQL transaction, row lock, or pool connection spans provider work. A returned output is validated and durably committed before the workflow advances. Large artifacts are content-hashed within the admitted namespace, written/fsynced with atomic publication before their references commit. Checkpoint commit checks authorized capture, matching input digest, current lease epoch, and permitted attempt reservation. It permits already-admitted calls to drain under PAUSE/STOP; it cannot admit a new call under either intent.
6. **Crash boundary:** A committed checkpoint survives a crash before DBOS step acknowledgement: replay returns it without invoking a model. A started capture with no checkpoint reuses its exact finalized input if RUN recovery continues it. Retry under an unchanged selection re-invokes that existing capture through an authorized reservation; it never recomposes or inserts a conflicting capture under the same unit key. Adopting a changed selection replans unfinished units into a new generation with fresh captures. If it was never invoked, composition remains pinned to its captured revision. PAUSE after loss leaves unfinished work suspended until Resume; STOP abandons unfinished calls without replay. No exactly-once provider guarantee for returned but uncommitted outputs. The coordination adapter supplies test-only fault injection at capture/input/output-commit/DBOS-ack boundaries for guarded recovery evidence; production configuration cannot activate it.
7. **Lease/takeover:** Database-clock bounded leases, short heartbeat renewals, and separate process lease epochs fence stale writers. Planned new attempts increment attempt fence only after acknowledged quiescence; recovery takeover after expiry advances lease epoch under lock. Do not bump the publication fence as soon as Stop is requested, because admitted outputs must still save. Do not rewrite original capture attribution when another attempt is authorized to finish it: use a separate reservation/adoption relation.
8. **Quiescence:** Acknowledge Paused only with no currently authorized provider call in flight, no returned output awaiting commit, and durable pending-work state. Paused attempts return and release all queue capacity, including any Studio parent slot. Interrupted unknown calls are unfinished; recovery honors stored control before replay. Stop follows the same drain then terminal path. Existing finite provider timeout and bounded retry contracts apply: when an admitted call exhausts them, record unfinished/failed work and proceed to the saved boundary; never claim successful output or a finished native call while it can still publish. If all required work is covered when Pause races completion, Completed wins; accepted STOP prevents Completed/Resume.
9. **Reconcile:** DBOS remains responsible for execution. A durable reconciliation workflow repairs enqueue-after-commit gaps and final acknowledgements after committed coverage, and detects expired leases/notifications lost. PostgreSQL notification is optional latency reduction, never a source of truth. Short tasks must not monopolize a paused workflow's queue slot.

The coordination pool is separate from DBOS internals, explicitly bounded for deployment capacity, and uses statement/lock timeouts. Worker routines validate allowed keys, IDs, source artifact namespace/hash, protocol, and fence; PUBLIC EXECUTE is revoked. Definer roles have only coordination-table privileges and no application-schema access. Fresh/upgrade grants follow the release asset's startup sequence.

## Planning and revised inputs

Canonical source anchors are stable against the pinned representation; extraction windows are not. Article contexts count schema-bearing requests and model reply budgets; generic Catalog uses schema-bearing discovery and character groups; recipe and unified Catalog use budgeted entry/discovery/verification windows. Changing schema, model/tokenizer, overlap, or budgets can move boundaries. Never identify a work unit only by an array index, a record ID, or a mutable window position.

Persist a planner-generation input, including a fixed historical-complete coverage snapshot taken at quiescence, before discovery; each discovery/provider call has its own capture/checkpoint. Never read changing coverage as replay input. Persist its deterministic resulting manifest/window set in one short transaction before dependent units start; unique publication identity includes generation, stage, and discovery-result digest, with identical replay returning the same manifest and inconsistent replay refused. Discovery can append a new immutable plan revision when further work becomes known, but replay cannot extend an already-published revision using different boundaries. Stage dependency digests determine which compatible intermediate checkpoints can be reused. All methods' provider choke points must pass through this adapter; a multi-call opaque step cannot satisfy call-level preservation.

At Paused or a durable Failed idle boundary, Studio can adopt a saved validated selection. Require Apply or explicit Discard for pending edits before Resume/Retry. Calls already started keep their selection/context. The new generation carries completed results as historical complete coverage with their original schema, even if the new schema differs; it does not implicitly reprocess them or mark a newly introduced field as already extracted. Replan only unfinished/unstarted work; retain incompatible intermediate checkpoints as history rather than using them as new-selection output.

Selected reprocessing is explicit: it adds a new plan/result version and preserves compatible manual corrections over the new model output. It cannot reopen a Stopped Extraction: any new processing after Stop creates a new linked Extraction, leaving the original terminal and its results intact. Added/removed/retyped/reinterpreted fields, or changed record boundaries, can make mappings incompatible; preserve and flag them. Historical values are still reviewed under their producing schemas. Strategy/source changes produce a new Extraction. Updating an Extraction never silently updates other running selections or account defaults; new admissions use the current durable schema/account choices as their start view displayed.

## Live review, feedback, and result visibility

The retained-result and feedback resolution comments are normative. Implementation must expose saved structurally valid values in all states, distinguish provisional/ungrounded/grounded and unprocessed/absent/failed, and keep review writes independent of model versions. Shape-valid per-field drafts persist without finalizing an entire partial review. Finalization targets a fixed result snapshot and validates complete required decisions under producing schemas; later values are pending. Boolean/array/object validation must use existing schema contracts, not assume today's scalar-only UI support covers every new value shape.

Each feedback candidate is a correction with its original context, not a generated universal rule. Select within the authenticated Project Context using stable field identity and validated equivalent-field mappings. Names/vector similarity alone never establish equivalence. Ungrounded compatible corrections are eligible; incompatible-for-target or excluded/superseded revisions are not. Do not implement automatic conflict detection/suppression/warnings. An optional Link evidence action validates published anchors in the correction's own source revision without blocking guidance or claiming semantic truth.

Each provider input records exact selected example revisions, formatting/compiler version, and reproducible prompt/context. A revision number alone is insufficient. Candidate snapshots are application data, not credentials. New target values must use their own source Evidence or be visibly ungrounded; examples do not supply target-source facts/anchors. A late response cannot resurrect superseded guidance or overwrite a newer correction.

## Researcher-facing API and interactions

Extend the existing `prototypes/studio/shared/extraction.contract.ts` and `packages/extraction` contracts together; preserve old capability-specific response interpretation.

| Surface | Contract |
| --- | --- |
| Read Extraction | Protocol capability; source/strategy pins; selected and producing inputs; derived lifecycle/control revision; latest snapshot; saved counts/coverage with honest unknown denominators; provisional/grounding/review flags. Available every state. |
| Control command | POST explicit pause/resume/stop/retry with command ID and expected control version. Return durable acceptance and derived state; acknowledgement may remain Pausing/Stopping until drain. 409 conflicts preserve local intent/draft; Stop is distinct from delete. |
| Save/adopt selection | Save schema reference and validated extraction-specific settings without mutating historical selection; adopt at acknowledged idle boundary with expected selection/control versions. Account settings change uses its existing explicit save surface. |
| Result pages | Snapshot-bound stable cursor plus result/record/field identities, producing revision, model and effective reviewed values, Evidence state, history references. Stable pages do not drift under appends/edits; refreshing opts into a new snapshot. |
| Review/edit/Evidence | Per-result/field expected revision, producing schema validation, optional own-source anchors; explicit conflict and saved version. Incompatibility warning links to historical correction and review; dismissal alone never makes guidance compatible. |
| Feedback inspection | Project-owned candidate history, inclusion/exclusion/supersession, per-target eligibility and budget omissions, actual examples consumed by a result. No automatic contradiction UI. |
| Export | Fix result/review snapshot and selected batch-member snapshots; CSV preservation bundle or revision-qualified XLSX. Values, historical/incompatible corrections, Evidence/proposals/status/attribution remain accessible; incomplete export never finalizes or resumes work. |
| Delete | Explicit owner-checked action (project lifecycle remains canonical), fencing and retained-reference removal before shared artifact GC. Stop/cancel is never deletion. |

Interaction defaults from the throwaway prototype: one clear lifecycle banner with saved/in-flight/pending counts, Pause/Resume/Stop/Retry and always-available export; results remain visible beside settings. Editing settings explains pause and in-flight behavior. Show an affected-field warning and count linking to incompatible corrections, and optional Evidence not linked / Link evidence. Keep full execution/feedback lineage available through progressive disclosure rather than flooding the normal flow with internal IDs. Accessible controls, focus retention, meaningful live announcements, and batch member state are required.

The prototype is a standalone HTML interaction model on `prototype/durable-interactive-extraction`, not a production design or persistence implementation. It models lost unsaved calls, saved selections, target-specific feedback, and fixed export snapshots; production fences, SQL transactions, and real grounding are validated separately. A numeric correction for the new field does not get projected into the historical text result; original correction history remains available.

## Export and retention mechanics

Extend `packages/extraction-result-export` and the Studio caller gates. A single values-only CSV cannot preserve revision/Evidence/proposal history, so CSV becomes a bundle of revision-qualified tables plus metadata/Evidence/review sidecars; XLSX uses companion sheets and unambiguous revision-qualified data. Explicit projection/repeated-field views are not a deletion of authoritative preservation data. Include saved partials from running/paused/failed/stopped batch members even if none succeeded. Export references a fixed snapshot and remains coherent under concurrent writes.

`packages/db/src/garbage-references.ts`, Studio garbage planning, and worker `deleteRuns` must protect canonical sources, checkpoint/result artifacts, review/Evidence history, and captured feedback source contexts. Paused/quiesced/terminal does not mean unreferenced. Preserve shared-reference behavior and existing worker boot/write-quiescence guards. Before explicit deletion, prohibit new captures and fence/abandon publication; late workflow responses cannot recreate the graph. Cleanup follows reachability and actual quiescence, not a guessed timeout alone.
