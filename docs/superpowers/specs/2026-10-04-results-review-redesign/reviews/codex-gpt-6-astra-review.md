Reviewed the current screenshots, prototype markup/CSS, and production contracts; exercised ReviewFlow’s logic in memory. The supplied directory lacks `support.js`, so layout findings are source-based, not browser-verified. No files changed.

1. **High — ReviewFlow, save status; States, saved state (`ReviewFlow.dc.html:420`, `States.dc.html:74`).** “Draft saved” is unconditional, and there are no saving, failed-save, conflict, or finalization-failure states. **Fix:** derive these from the existing review controller; retain visible retry/conflict recovery, and distinguish “all decisions made” from “review saved.”

2. **High — Main, evidence vocabulary (`Main.dc.html:85`).** “Verified” implies correctness; “Unchecked” combines failed/incomplete verification with intentional policy exclusion; “Weak link” is presented as an alternative to link origin although either verifier-linked or rule-linked evidence can be doubtful. **Fix:** preserve `claimStates.ts` outcomes and origin separately, use “Verifier-supported,” retain “Not completed” and “Excluded by policy,” and make doubtful-link warnings an additional attribute; unknown accounting must remain unknown.

3. **High — ReviewFlow, edited values and evidence (`ReviewFlow.dc.html:487`, `:493`, `:552`).** Editing changes the displayed value but leaves its original “Verified” explanation and quote attached without qualification—even after rejection. **Fix:** display original and reviewed values explicitly, label the existing evidence “Evidence for extracted value,” and suppress obsolete warnings as production `evidenceDetail()` already does.

4. **High — ReviewFlow and CalmRail, Undo (`ReviewFlow.dc.html:460`, `:468`; `CalmRail.dc.html:358`).** In-memory checks confirm that undoing an edit leaves the corrected value displayed, while undoing a bulk approval leaves the value Approved; focus mode offers no immediate undo. **Fix:** restore the previous decision **and** value, represent bulk approval as explicit decisions, and provide an undo action after auto-advance with the design-system toast timing.

5. **High — ReviewFlow, missing/unsupported values (`ReviewFlow.dc.html:387`, `:438`, `:497`).** “Missing” is explained as the model finding nothing, but production deliberately distinguishes empty values caused by conflicting candidates; “nothing to review against” also turns optional attention into a dead end. **Fix:** retain a “Conflicting evidence” state with candidates, describe missing values without inventing a cause, and preserve field guidance/edit access; any optional correction must follow the evidence-backed correction contract.

6. **High — ReviewFlow, record navigation and progress (`ReviewFlow.dc.html:318`, `:388`, `:515`, `:551`).** Only Grav 8 participates in the queue, other record headers and “Continue with record 2” have no handlers, and the position combines global decisions with a local queue; seven approvals finish the record with 53 decisions remaining. **Fix:** define a queue keyed by full result paths across records, show separate record/global progress, and specify Article, nested-array, document-field, and empty-Catalog behavior.

7. **High — ReviewFlow and CalmRail, selected-row expansion (`ReviewFlow.dc.html:96`, `:102`, `:295`; `States.dc.html:119`, `:134`).** The non-wrapping decision group plus another “One by one” control must fit inside a heavily indented expansion, while highlighted quote text cannot wrap; the narrow boards omit that expansion and omit focus-mode entry entirely. **Fix:** keep mode entry in one stable header location, give decisions their own wrapping/full-width row, allow quote wrapping, and demonstrate the actual selected/editing/focus states at both widths.

8. **High — ReviewFlow, document synchronization (`ReviewFlow.dc.html:183`, `:498`, `:510`).** Selection changes classes on a hand-authored page but defines no page navigation or scrolling in either direction, and every example implies a precise text location although production supports cell, block, and whole-input anchors. **Fix:** connect selection through result paths and evidence-anchor IDs, reveal the corresponding page/row, expose actual precision, and provide a Markdown/location fallback when PDF geometry is unavailable.

9. **High — ReviewFlow and FocusReview, keyboard/focus contract (`ReviewFlow.dc.html:361`, `:395`, `:411`; `FocusReview.dc.html:140`).** The advertised shortcuts have no handlers, and there is no focus transfer/restoration when rows disappear, modes change, or overlays open; `role="menu"` and `role="dialog"` alone do not supply that behavior. **Fix:** implement scoped shortcuts that ignore text entry and repetition, define Escape precedence, manage overlay focus, and announce the next field/value after auto-advance. These are also required by the [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md).

10. **Med — ReviewFlow, edit lifecycle (`ReviewFlow.dc.html:498`, `:504`, `:513`, `:563`).** Selecting another value or changing modes silently abandons the draft, all edits become strings, and saving an empty string displays the original value because of `||` fallback. **Fix:** preserve drafts by result path or require explicit cancellation, use schema-aware parsing/validation, and distinguish absent overrides from valid empty values.

11. **Med — ReviewFlow, list ↔ focus and Skip (`ReviewFlow.dc.html:558`, `:559`, `:566`).** Returning to List forces “All,” losing the researcher’s filter; “Skip for now” merely moves one position and can revisit an already-decided value without showing its decision in the main focus view. **Fix:** restore filter, selection, and scroll position; define skip as postponing an undecided item, and show decision state with explicit revision controls when revisiting completed items.

12. **Med — ReviewFlow, bulk approval (`ReviewFlow.dc.html:403`).** “Approve rest” sits beside filtered results but applies globally, without naming the records or doubtful links included; it also remains available during an active edit. **Fix:** confirm “Approve N remaining values across M records, including W doubtful links,” state that filters do not limit the operation, and disable it until the edit is resolved.

13. **Med — States, extraction lifecycle (`States.dc.html:58`, `:91`, `:111`).** A source-cut record is used to explain incomplete processing even though ReviewFlow permits that condition in a completed extraction; the running board promises incremental values and a determinate percentage without an established contract, while queued, stopping, cancelled, and empty-result states are absent. **Fix:** derive processing status from the attempt, report source truncation separately, and design only progress and recovery states supported by the controller.

14. **Med — ReviewFlow and FocusReview, dimming and queue markers (`ReviewFlow.dc.html:127`, `:143`, `:334`).** Dimming document text to 28% opacity makes surrounding context—and focus indicators inside it—hard to read; queue decisions are distinguished visually only by colour, with 16px targets and 6px gaps. **Fix:** make dimming optional and restore context on focus, use decision glyphs plus an accessible current-item state, and enlarge target areas without crowding adjacent controls.

15. **Low — ReviewFlow, hierarchy and tokens (`ReviewFlow.dc.html:98`, `:101`, `:234`, `:344`).** The rail adds 11.5/13.5/14.5/20/26px typography, raw colours, and several competing progress/navigation treatments beyond DESIGN.md’s four-size rail scale. **Fix:** use shared tokens, reduce focus mode to one progress summary and one navigation treatment, and keep the single filled primary reserved for the active review action.
