# Fable 5.1 review of the prototypes (2026-10-04, before fixes 1–5 were applied)

Line numbers refer to the prototype version reviewed then, not the current files.

1. high · ReviewFlow / Main — "Weak link" is modelled as a third sibling of Verified / Rule-linked ("72 verified · 0 rule-linked · 6 weak links" sums to 78 of 72 claims; queue sorts weak first as if it were a state). In code it is orthogonal: `evidenceCheck()` (ResultsTab.tsx:86) flags a supported link as "not found in passage" or "also in N other passages"; `claimStates.ts` has no such state. The `sex` reason ("source marks it uncertain with (?)") is invented. Fix: weak = boolean modifier on a Verified/Rule-linked row, counts read "72 verified, 6 doubtful", the expansion shows the code's two reasons verbatim.
2. high · "Approve rest…" approves all 72 across all records, and in production `ResultsTab.tsx:500–505` auto-accepts the moment every required decision exists, so this (and the last "Approve and next") silently finalises and locks the review. The prototype still offered per-row Undo, a no-op after bulk. Fix: label "Approve the rest and save review (final)", ModalDialog with focus return, disable while `editingPaths.size>0`, warn before the last to-check value. Or change the product rule so approve-all leaves a draft and "Save review" is explicit.
3. high · distinctions the code keeps are dropped: (a) Contested (`openContested`, `ContestedBadge`, candidates) has no vocabulary; (b) "Unchecked" lumps `not_completed` (failure with reasons) with `excluded` (schema policy); (c) ungrounded values with no claim accounting are unnamed, "whether checks finished is not known" (claimStates.ts:31–33); (d) no row shows Rule-linked. Fix: states = Verified, Rule-linked, Unsupported, Check not completed (+reason), Not verified by policy (+policy name), No evidence (no accounting), Missing, Contested (candidates in expansion). Filter "Not reviewable" groups them but the row word stays precise.
4. high · one-by-one has no keyboard model behind the kbd badges (no keydown; A/E/R/J/K would fire while typing; Esc both "List" and cancel-edit), no undo, no focus management. Fix: key handler on the rail container, ignored when target is an input; Z / toast undo; decided value in focus shows decision + Undo; after advance move focus to the value heading (tabindex=-1) or aria-live polite; Enter on "Continue with record 2".
5. high · the doc side assumes inline marks and paragraph-level dimming on DOM text. Production is a PDF with `onSelectEvidence(anchorId)` only; Evidence Anchors are text/cells "without visual geometry" (CONTEXT.md), `precision:'input'` links point at a whole page, several values can share one anchor (passage→value is many-to-one). Dim at opacity .28 makes context unreadable. Fix: specify anchorId→rects from the PDF text layer, dim only for cell/segment precision and only beyond ±1 block, use ≥.55, and on an ambiguous passage click show a small "Values in this passage" list.
6. med · the header has no home for: `monitorError`/Reconnect, draft errors incl. `REVIEW_DRAFT_CONFLICT` "Reload server review", `review.error` + Retry, the "Save review" button for the no-evidence case, `inspectedAttempt`/`readOnly` (historical attempt), `headerExtras` (snapshot choice, "Open latest reviewed"), `RecipeReview`/`CatalogReview`, and the Article strategy (no records) which needs a flat list. Fix: a second status line for transient state (saving/draft/error/reconnect) and an Article variant of the body.
7. med · in one-by-one the Run button was restyled to outline so the rail could hold the one filled primary; contradicts DESIGN.md §5. Fix: keep Run filled; make "Approve and next" green outlined. (Applied.)
8. med · filter chip counts mix universes (claims vs fields); clicking a doc mark and leaving focus mode reset the filter. Fix: counts in claim terms, "All" uncounted, never reset the filter; pin a hidden selected value as "outside filter". (Applied.)
9. med · selected row: no terracotta edge (DESIGN: terracotta marks selection), chip disappears on select, nowrap mark overflows at 264/344, no clamp on long values, srcLabel string-split from meta. Fix: inset 2px accent edge on `.row.sel`, keep the chip, drop nowrap, line-clamp 2 + title, real `{page, origin, doubt, reason}` fields.
10. med · queue dots and decided doc marks distinguished by colour only. Fix: glyphs inside 20–24px squares; decided marks change shape (underline weight), not just hue. (Applied.)
11. med · a11y semantics: role=tab without tabpanel; aria-expanded without aria-controls; a role=status count line re-announcing on every decision; dialogs without aria-modal/focus trap/return (reuse `ModalDialog` returnFocusRef); doc marks without accessible names or aria-current. Announce only the delta.
12. med · hit targets under 24px (.evc 22px, .qd 16px, .lnk ~22px).
13. med · duplicated controls ("One by one" header and row with the same label; "Schema rev 2" and ⓘ both open the drawer; "Copy link" in a global menu; Export buried in ⋯ during review but visible once saved). Fix: row ghost "Review from here" (applied); Schema link opens the used schema; Export always visible secondary; menu items disabled with reason when nothing is selected.
14. low · type sizes off the rail scale (13.5, 11.5, 14.5, 16, 20, 26). Snap to 13/12/11; add one display size (20) to DESIGN.md if the count and focus value keep it. (Partly applied: 20 kept as display size.)
15. low · Edit is a bare text input (production values are typed; ResultValue handles that); "Edit field" (schema, `onEditField`) has no home; end-card copy hard-coded. Fix: reuse ResultValue's editor; "Edit field…" in an expanded row's menu; generate copy from counts.

Verdict: direction right; was not honest yet (weak/contested/policy/no-accounting mis-modelled, bulk/last approve silently finalises). Items 6 and 11 list what ResultsTab.tsx already handles that the boards forgot.
