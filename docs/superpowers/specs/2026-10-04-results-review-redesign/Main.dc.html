What gets in the way

Six problems

1

One number, said four times

72 appears as the tab badge, in Review attention, as “72 of 72 remaining” and on “Approve remaining (72)”. Each is a different component with its own wording.

2

The same counts, twice

Pills and the three Completion lines repeat each other (Verifier-supported 72 is in both). Neither tells you what to do next.

3

Seven words for the state of a value

to check doubtful link unsupported missing ungrounded not completed excluded. Each one is accurate, but they overlap, and nothing says which ones you have to act on.

4

Three levels of tabs; Markdown is in the wrong pane

Schema/Results, then Review / Values as code / Markdown on the same line as the buttons. Markdown is a view of the document, so it belongs next to the PDF, not under Results.

5

Drilling down hides the rest

Root › Item 1 › grave_goods shows one level at a time, and its back and forward buttons duplicate the browser’s. You can’t see a record and its children together.

6

Every explanation is always on screen

Paragraphs about approval rules and catalog coverage are important, but they apply once. They should be one click away, not taking up space on every visit.

↔

The document only follows the rail, never the other way

Clicking a value highlights one passage. The page shows no other claims, the thumbnails don’t show where work is left, and clicking a passage doesn’t select its value.

Proposed vocabulary (states as in claimStates.ts)

Two questions, two sets of words

Your decision · 4 words

  • To check
    the only state that needs you
  • Approved
  • Edited
  • Rejected

Evidence · words from claimStates.ts

  • Verifier-supported
    the verifier linked a passage
  • Linked by rule
    a key or structure rule linked it; no verifier checked it
  • + Doubtful link
    a flag on either: “value not found in the linked passage” or “also appears in N other passages”
  • Unsupported
    every check finished; none found a passage
  • Not completed
    the check didn’t finish; the reason is shown
  • Excluded by policy
    the schema asked for no verification; the policy is named
  • No evidence
    no accounting, so whether checks finished is unknown
  • Contested
    sources disagreed; the candidates are shown
  • Missing
    no value was extracted

Only To check asks for action, and only linked values get there, doubtful links first. Everything below the line is listed with its reason but never blocks saving. The review saves itself, read-only, when the last linked value gets a decision, so the UI says so before that click.
