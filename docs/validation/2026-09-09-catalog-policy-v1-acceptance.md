## Reading the numbers

- Calls fall 4.2 times; wall time falls 13% (92 against 106 minutes).
  Output tokens are the floor: the batched calls produce the same values,
  so the model generates nearly the same 167,000 output tokens and saves
  only prompt and turnaround overhead. Discovery is untouched (9.5 against
  9.1 minutes).
- The repeated-passage drop from 1,313 to 30 is mostly not the policy. The
  production run counted a value's repeats across the whole document (the
  `fa_code` value `EF` reached 178); PR #132, merged the morning after that
  run, scoped grounding candidates and the repeat count to the entry's own
  passages, and this run includes it. The policy's own contribution is the
  non-verbatim count (363 to 294), from field-aware grounding.
- Values agree with the production run in most entries, and the
  disagreements are the model's usual variation, in both directions:

| field | equal | punctuation only | this run shorter | production shorter | other |
|---|---:|---:|---:|---:|---:|
| catalogue_label | 419 | 0 | 0 | 0 | 1 |
| locality_and_findspot | 242 | 41 | 39 | 85 | 13 |
| fa_code | 314 | 61 | 25 | 20 | 0 |
| find_description | 236 | 0 | 57 | 39 | 88 |

  The one `catalogue_label` difference is entry 271, printed `271,` in the
  scan and copied verbatim by this run; the production run had normalised it
  to `271.`. List fields: `museum_inventory` 445
  items against 464, `literature_references`
  1364 against 1373.
  Neither run is a reference; these counts say the batched calls did not
  systematically drop content, not which run is right.

## Caveats

- Single run; Ollama on Spark is not bit-reproducible across processes.
- The harness bypasses the Studio job worker and persistence, so the
  Studio-side accounting (per-record diagnostics, "To check" badge, review
  workflow) was verified in unit tests, not in this run. The first Studio
  Catalog run under the new default should be compared against this record.
- Value quality against a reference was measured on the 29-entry excerpt
  (203/203 values, 164/164 supported fields), not on all 420 entries.
