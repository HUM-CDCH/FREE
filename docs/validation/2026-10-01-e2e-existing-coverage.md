# Existing E2E coverage inventory

Date: 2026-10-01. Status: repository-source analysis completed; no tests were executed for this inventory. This records assertions present in the current Playwright source, not a passing-run report. It supports the accompanying UX/user-story catalogue and should be read against the normative [product contract](../../README.md#product-contract).

## Test tiers and their boundaries

| Tier | Entry point and scope | What remains substituted |
| --- | --- | --- |
| Default browser suite | `pnpm test:e2e` first runs [playwright.config.ts](../../prototypes/studio/playwright.config.ts): real Studio, disposable Docker PostgreSQL, mock OIDC, bounded browser concurrency. It excludes recovery and real-service specs. | Many individual specs intercept application API responses; the canonical lifecycle uses a DBOS Parsing Service stand-in. |
| Recovery browser suite | The same `test:e2e` script then runs [playwright.recovery.config.ts](../../prototypes/studio/playwright.recovery.config.ts): one worker, restartable Studio, pinned session secret, state/log artifacts. | Parsing Service/model boundaries use controlled stand-ins, enabling held calls and restart timing. |
| Real-service suite | `pnpm test:service` runs [playwright.service.config.ts](../../prototypes/studio/playwright.service.config.ts): Python API/worker and native parsing, one Chromium worker, separate state/database. | [realService.ts](../../prototypes/studio/e2e/realService.ts) scripts the extraction model boundary by default. Both `FREE_REAL_EXTRACT_URL` and `FREE_REAL_EXTRACT_MODEL` enable a live model; several deterministic cases then skip. |
| Base-path browser suite | `pnpm --filter studio test:e2e:base-path` runs [playwright.base-path.config.ts](../../prototypes/studio/playwright.base-path.config.ts) under `/free`. | Only the canonical lifecycle spec is selected; this is not a repetition of every browser workflow behind the production proxy. |

The commands are defined in the [Studio package](../../prototypes/studio/package.json) and [root package](../../package.json). `test:all` includes default/recovery E2E and real-service; `test:all:node` excludes the Python service tier. The README says CI currently runs the Node aggregate and that real-service and live-model evidence are obtained locally. The full disposable Compose `test:system` tier is separate from Playwright and deliberately outside those aggregates. [Verification contract](../../README.md#verification).

## Highest-value additions to the story suite

These are gaps in the inspected **browser assertions**, not claims that the application lacks the feature or that lower test tiers lack coverage.

1. **Real review concurrency and reset:** add two real browser tabs editing the same extraction draft against PostgreSQL, conflict recovery without silent overwrites, invalid/partial finalization refusal, and the full Revert all journey with restored raw values, pending decisions, retained revision history and resulting export. The normative contract explicitly requires these behaviors; the canonical lifecycle currently proves persisted partial review and completion, while the batch fixture checks mocked draft conflicts. [Contract](../../README.md#product-contract), [canonical review assertions](../../prototypes/studio/e2e/canonical-evidence-lifecycle.spec.ts), [batch fixture](../../prototypes/studio/e2e/batch-extraction-export.spec.ts).
2. **Ownership matrix across all resources:** extend the current foreign-extraction read and two-account model configuration assertions to direct routes and writes for projects, sources, retained artifacts/evidence, schemas, batches, drafts and final reviews. Cover account switch while a request/workflow is in flight. [Contract](../../README.md#product-contract), [authentication spec](../../prototypes/studio/e2e/authentication-accessibility.spec.ts), [canonical lifecycle](../../prototypes/studio/e2e/canonical-evidence-lifecycle.spec.ts).
3. **Browser-only creation-to-deletion journey:** drive project creation, upload, schema authorship/approval, extraction, review/export, rename and confirmed deletion through visible controls against durable services. Existing navigation fixtures cover excellent failure/focus behavior; real-service journeys often bypass controls for setup, and deletion is currently asserted through an API/GC path. [Navigation spec](../../prototypes/studio/e2e/project-navigation.spec.ts), [service spec](../../prototypes/studio/e2e/real-service.spec.ts), [GC spec](../../prototypes/studio/e2e/real-service-gc.spec.ts).
4. **Full schema editor and provider choice matrices:** catalogue then cover schema node types/nesting, add/remove/reorder/validation and proposal acceptance alongside the existing clipboard/order/reload regression cases. Cover visible connection add/edit/delete and selected provider discovery/error flows alongside existing key and route security cases. [Critical flows](../../prototypes/studio/e2e/critical-flows.spec.ts), [schema order](../../prototypes/studio/e2e/schema-order-lifecycle.spec.ts), [interactive reload](../../prototypes/studio/e2e/interactive-reload.spec.ts), [model configuration](../../prototypes/studio/e2e/model-configuration.spec.ts).
5. **Deployment and browser environment matrix:** expand `/free` beyond the canonical lifecycle, and decide separate coverage for proxy-routed HTTPS, external Entra, additional browser engines and scanned OCR/layout inputs. The current configs have no multi-browser `projects` matrix; real-service disables CUDA and scripts the model by default. Layout checks use predefined viewport sizes; the 200% helper halves CSS viewport dimensions and does not manipulate browser zoom or establish screen-reader conformance. [Configs](../../prototypes/studio/playwright.config.ts), [base-path config](../../prototypes/studio/playwright.base-path.config.ts), [real-service fixture](../../prototypes/studio/e2e/realService.ts), [accessibility helper](../../prototypes/studio/e2e/accessibility.ts).

## Fixture constraints for future test design

- Reuse [auth.ts](../../prototypes/studio/e2e/auth.ts) for the real session path. It deliberately prevents broad API fixtures from replacing `/api/auth/session`, and supports canonical mock identities and the `/free` prefix.
- Preserve the disposable stack target/lifecycle boundaries in the [README](../../README.md#safety-boundaries) and [Playwright stack](../../prototypes/studio/e2e/playwrightStack.ts). Several database-backed specs explicitly skip unless `DATABASE_URL === EXTRACTION_TEST_DATABASE_URL`; a green invocation with skips is not coverage evidence for those workflows.
- Keep held calls and process-kill scenarios in the one-worker recovery/service configurations. The default suite shares OIDC and Studio and already caps workers for reproducibility. [Default config](../../prototypes/studio/playwright.config.ts), [recovery config](../../prototypes/studio/playwright.recovery.config.ts), [service config](../../prototypes/studio/playwright.service.config.ts).
- Store assertion provenance per new story: UI with mocked API, real Studio/database with service stand-in, real Python service with scripted model, or live external service/model. Test names alone cannot establish which boundary was exercised. The inventory above provides that distinction from source; fresh execution reports must separately record command, selected config, skips, environment and artifacts.
