FIG. 3 — TASK LIFECYCLE

Accept fast, parse in the background, survive restarts

POST /tasks does the trust-boundary work inline and returns 202 immediately; parsing happens in a background worker holding a per-task file lock. Two standing loops keep the store honest across crashes and time.

1 · ingest

Upload → magic bytes + 50 MB streamed cap. URL → SSRF validation, pinned connects, per-hop redirect checks.

2 · address

SHA-256 the bytes → document_id; hard-link into data/sources/ under a store lock + lease. Same PDF twice = same blob.

3 · record

metadata.json written atomically under the task-store lock, after a quota check (507 when the store is full).

4 · respond 202

Caller gets task_id + content_sha256 and starts polling; BackgroundTasks hands off to the worker.

5 · work

Per-task lock → admission Semaphore(1) → build or reuse the canonical document (fig. 4) → copy result into the task dir.

TASK STATE pending→ running→ completed or failed document status may add completed_with_warnings · parser runs: success / failed / skipped

lifespan · reconcile_interrupted_tasks()

At boot, every task found pending/running is finished from a digest-validated canonical cache — or failed with error_code: task_interrupted. Never silently re-queued.

lifespan · cleanup_loop()

Hourly sweep: unpublished task directories past the 24 h retention window are removed (skipping locked ones); completed tasks are retained indefinitely; orphaned .pending/ builds and unreferenced blobs are pruned.

Failure surfaces are explicit: 400 malformed request · 413 oversized upload · 415 wrong type · 422 unsafe URL · 507 storage quota. A failed parse writes error_code + a public-safe message into task metadata — source URLs never reach the logs.

FIG. 4 — CANONICAL PARSING PIPELINE

The orchestrator: verify, never guess

One deterministic path from bytes to contract, run per content hash, not per task. Its governing rule: page identity and offsets are published only when verified — uncertainty becomes explicit absence, never a fabricated span.

FIG. 5 — STORAGE & CACHE IDENTITY

Three stores separate request state, source bytes, and reusable parsing work

The service has one filesystem root but three different identities. A task UUID names one request, a SHA-256 digest names one exact PDF byte sequence, and a preprocessing configuration hash decides whether an existing canonical parse may be reused. Two submissions of identical bytes therefore produce two tasks, one source blob, and—when policy still matches—one canonical generation.

1 · task store — request identity

data/tasks/
├─ .locks/
│  ├─ store.lock               aggregate writes + quota
│  └─ {task_id}.lock           one worker / cleanup guard
└─ {task_id}/                  canonical UUID · mutable
   ├─ metadata.json            state, refs, errors, stats
   ├─ source.pdf               fixed internal name
   ├─ parsed_document.json     task-bound public view
   └─ {task_id}.zip            on-demand, cached archive

Owns: request lifecycle and task-specific source metadata. The display filename is metadata only; it is never used to construct a path.

2 · source store — byte identity

data/sources/
├─ .store.lock                 publish + prune transaction
├─ .leases/
│  └─ {sha256}.{task_id}       30 min ingest protection
└─ {sha256}.pdf                immutable authenticated blob

source.pdf ── hard link ───────┘
Falls back to an independent task copy when
the stores do not share a hard-link-capable fs.

Owns: exact source bytes, independent of filename or URL. Publication hashes before and after the temporary-file commit.

3 · document store — parsing identity

data/documents/
├─ .locks/store.lock           quota + publication
├─ .locks/{sha256}.lock        one build per source
└─ {sha256}/
   ├─ parsed_document.json     atomic canonical commit
   ├─ .pending/{generation}/  unpublished build
   └─ generations/
      └─ {cfg[0:16]}-{uuid32}/ immutable artifacts
         └─ artifacts/
            ├─ pymupdf_inspection.json
            └─ docling/
               ├─ document.docling.json
               ├─ document.doctags
               ├─ document.aggregate.doctags (optional)
               ├─ document.llm.md
               └─ document.diagnostic.md

Owns: reusable parser results. The generation is immutable; the top-level manifest is the replaceable pointer to the currently committed generation.

Identity and sharing rules
Concept Computed from Sharing behavior What a change means
task_id New UUID for every accepted POST /tasks Never shared, even for duplicate submissions A separate lifecycle, filename/URL, status, errors, archive, and API projection
content_sha256 Exact bytes of the validated PDF Shared by every task with byte-identical input Any byte change creates a new source blob and document directory
config_hash Canonical conversion policy, resolved OCR device and DPI, parser/model versions, policy revision Must match the canonical manifest before cache reuse Same source bytes parse into a fresh generation under changed policy
generation Config-hash prefix plus a random UUID, inside the source-hash directory Artifacts are immutable after publication parsed_document.json atomically moves the canonical pointer; old referenced generations survive cleanup

1 stage + validate

Stream upload or SSRF-safe download to tasks/{id}/source.pdf; enforce PDF magic and the 50 MiB request cap.

2 authenticate + publish

Compute SHA-256, acquire the source-store lock, create a lease, publish through a temporary file, verify again, then hard-link the task copy.

3 commit task record

Atomically write pending metadata.json with source and canonical refs under the task-store lock; then release the source lease.

4 reuse or build

The worker authenticates both source copies. A valid cache returns immediately; otherwise artifacts are built under .pending/.

5 bind to task

Publish the generation, commit the canonical manifest, then write a task-local document whose filename, URL, timestamps, and refs belong to this task.

cache acceptance is an authentication step

  • Canonical source hash and derived document ID must match the task.
  • preprocessing.config_hash must match the current resolved policy.
  • Artifact refs must resolve to regular, non-symlink files beneath data/documents/{sha256}/.
  • Recorded parser input digests must match the source; recorded output digests are recomputed before reuse.
  • A missing, corrupt, escaped, or policy-stale cache is ignored and rebuilt rather than partially trusted.

publication is immutable generation + mutable commit pointer

  • Lock order is task → task-store and document-store → per-source document lock.
  • Reserve conservative capacity before expensive parsing, then validate exact projected bytes before commit.
  • Build under .pending/, rewrite refs to the final path, and atomically rename the whole generation.
  • Validate the published generation, then atomically replace the top-level canonical manifest last.
  • Failure removes the pending/new generation; an older committed manifest remains readable.

task rebinding keeps shared results private to each request

  • The canonical result is source-scoped, but public task responses must not inherit the first task's filename, URL, or creation time.
  • rebind_parsed_document_for_task() overlays source kind, sanitized display name, public URL, byte size, creation time, and task-local refs.
  • If a task-local document is absent, reads can load the canonical manifest and apply the same rebinding dynamically.
  • GET /markdown serves the canonical embedded text view; the download route packages task JSON plus only confined canonical artifacts.

hourly cleanup follows references, leases, age, and quotas

  • Inactive task directories older than 24 hours are removed only after acquiring their task lock, and only if the task never published: a completed task is the pinned artifact reference a consumer's own store keeps, so it never expires.
  • Source blobs named by remaining task metadata or a live lease are protected; unreferenced blobs are removed oldest-first when the 1 GiB source quota requires space.
  • All crash-abandoned .pending/ builds are removed. Published generations survive only while a canonical or task-local manifest references them.
  • Unreferenced document directories are retained for seven days unless the 4 GiB document quota requires earlier oldest-first eviction.
  • Referenced data is never evicted to force admission; a new task fails with a storage error when protected content consumes the budget.
Default operational limits
Boundary Limit Scope Notes
upload / URL download 50 MiB One incoming Source Document Streamed cap applied before parsing; URL downloads also have redirect and total-time limits.
task 256 MiB each · 2 GiB total data/tasks/ Aggregate accounting deduplicates hard links by inode. Task ZIP inputs and generated archive are capped at 256 MiB. Completed tasks are retained until deleted, so the total is a real ceiling on retained Source Documents.
source 1 GiB total data/sources/ Only unreferenced, unleased blobs are eviction candidates; ingest leases expire after 30 minutes.
canonical document 512 MiB each · 4 GiB total data/documents/ Unreferenced document retention is seven days; protected documents can make new admission fail.
worker admission 1 parse Per service process A semaphore bounds expensive parsing even when many task requests are pending.

path and reference invariants

  • Task directories accept canonical UUIDs only; source and document keys accept lowercase 64-character SHA-256 values only.
  • Generation IDs must match the config-prefix/UUID shape, and all constructed paths are resolved back beneath their service-owned base.
  • The internal source name is always source.pdf; sanitized researcher-facing names remain metadata.
  • Canonical artifacts may not be symlinks, and download assembly rechecks that every ref remains under the matching document root.

scope caveat — operational storage, not FREE domain persistence

  • These stores persist parsing tasks, immutable source bytes, canonical text views, parser provenance, and downloadable artifacts.
  • They do not yet persist Project Contexts, annotations, annotation sets, extraction schemas, extractions, extraction results, or review decisions.
  • That is why the prototype can have durable parsing caches while the broader FREE architecture still describes its domain persistence layer as not yet implemented.

Reference chain: task metadata → content_sha256 → source blob + canonical manifest → immutable generation artifacts. Task cleanup removes the first reference; later source/document pruning may reclaim the now-unreferenced shared data according to leases, retention, and quotas. It does not synchronously delete shared content merely because one task disappears.
